- 2026-10-02: **Backend decisions (client's choice, overriding SPEC/CLAUDE.md where noted):**
  - **Auth is JWT, not express-session** (overrides SPEC §3.2, CLAUDE.md §23–24). To keep the spec's guarantees: short access tokens (15 min, `JWT_ACCESS_TTL_SECONDS`) + opaque rotating refresh tokens stored *hashed* in MongoDB (revocable on block/password change, reuse detection); the user's role/status/permissions are loaded from the DB on every request (≤ 30 s cache), so blocking takes effect immediately; web tokens travel in httpOnly cookies (XSS-safe, `apiServer()` cookie forwarding unchanged) and `Authorization: Bearer` is accepted for the future mobile app; customer and staff tokens use separate secrets, cookies and `aud` claims, so a customer token can never pass the admin guard. Refresh lifetimes mirror the spec's sessions: 30 days rolling (customers), 12 hours absolute (staff).
  - **Request DTOs use class-validator classes, not Zod** (overrides CLAUDE.md §9 "Zod at API boundaries"). Business rules still come from `@aricon/shared` (pricing/tier validation, permissions, order state machine) — DTOs validate shape only. Zod stays for env validation (internal config, needs per-profile cross-field rules).
  - **Swagger/OpenAPI** at `/api/docs` in development/test only.
  - **Spring-style layering**: `controller → service → repository (BaseRepository) → Mongoose model`; cross-cutting concerns registered once in `CommonModule` (global exception filter = `@ControllerAdvice`, response-envelope interceptor, validation pipe, rate-limit + Origin guards); typed `AppConfig` (= `@ConfigurationProperties`).
  - **Profiles**: `NODE_ENV` = development | test | production; `.env.{profile}.local` → `.env.{profile}` → `.env.local` (not in test) → `.env`. `.env.development` and `.env.test` are committed with `dev-only-` placeholder secrets; production reads only the server environment and refuses dev secrets, http `APP_URL`, local storage or missing SMTP.
  - CSRF: an Origin guard on non-GET requests that carry cookies (cookie auth); Bearer clients without cookies pass. `@SkipOriginCheck()` is reserved for `POST /api/public/rfp`.
  - API port is 4000 (the Nest scaffold defaulted to 3000, clashing with the web app). The `nest new` scaffold's empty nested `apps/api/.git` was removed so the main repo tracks the API.
  - Order placement reads the cart, products, settings and address **inside** the order transaction (snapshot isolation), not just the stock writes: a concurrent order or admin price edit causes a write conflict, the driver re-runs the placement on fresh data, and the customer gets `OUT_OF_STOCK` / `PRICE_CHANGED` instead of a stale price. The decrement itself is `findOneAndUpdate` with `$elemMatch: { _id, isActive, stock ≥ qty }` + positional `$inc` (same guarantee as SPEC §6.6's arrayFilters `updateOne`, and it returns `stockAfter` for the movement in one round trip).
  - Reference-data lists (categories, brands, delivery areas, riders, staff) return full arrays, not pages: they are short, fixed-size lists the admin uses in selects. Orders, products, customers, stock movements and audit logs are paginated (max 100).
  - `GET /api/admin/orders` also returns `statusCounts` (same filters minus status) for the status tabs (SPEC §10.4).
  - Admin writes run in a transaction together with their audit entry, so an entry exists if and only if the change committed. Two admins demoting each other at the same moment can't both pass the "one active admin" check: every admin role/status change bumps a lock counter, so concurrent ones conflict and are retried.
  - Revalidation calls are batched in-process (2 s for edits, 60 s for stock changes per SPEC §14) instead of an Agenda job for now; a lost batch only delays pages until their 300 s ISR refresh. The web side is `apps/web/app/%5Finternal/revalidate/route.ts` (served at `/_internal/revalidate`; `_` folders are private in the App Router), which expires tags immediately (`revalidateTag(tag, { expire: 0 })`) so a changed price is never served stale. Nginx must block `/_internal`.
  - `CACHE_TAGS` moved into `@aricon/shared` (the web re-exports it), `permissionCatalog()` too, and `karachiDayStart/End` were added for date filters. `AdminSettingsDTO.updatedAt` is nullable (null until first saved).
  - Small additions not spelled out in SPEC: index `products.variants._id` (`PUT /api/cart/items` sends only a variant id); `PUT/DELETE /api/cart/items` and `merge` also take `?areaId=` and answer with the priced cart; address endpoints answer with the whole updated list (the default can move); `POST /api/account/change-password` is rate-limited (10/15 min) because the current-password check doesn't count toward lockout; `ReorderResultDTO` gained `cart` (SPEC §7.2 says reorder returns "cart + skipped items"); malformed `:slug`/`:id`/`:orderNumber` params answer 404 rather than 400.
